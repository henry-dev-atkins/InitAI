# Technical writing

State the answer, decision, or result near the start.

Give each paragraph one job.

Explain what happens, why it happens, and what the reader should do.

Name the actor for important actions.

Use the repository's accepted terms consistently.

Preserve commands, paths, identifiers, numbers, units, conditions, and uncertainty.

Use a list for independent items or ordered steps.

Use prose when the relationship between ideas matters.

Prefer a precise verb over an abstract noun.

Cut repeated introductions, empty qualifiers, generic headings, and conclusions that add no decision.

Do not add a claim, example, result, or cause that the source does not support.

Use British English and sentence-case headings.

For agent-facing text, apply `$simplified-technical-english` after drafting.

For analytical free text, apply `$henrys-voice` when the user asks for that voice.

Return the requested document. Add editorial comments only when the user requests review.
